4. GLOBAL VARIABLE / API KEY BINDING (GEMINI_API_KEY — MUST NOT BE WRITTEN LITERALLY)
------------------------------------------------------------------------------------
- Context7 (/websites/langflow): Global variables are stored encrypted in the Langflow DB;
  two types: Generic (visible) and Credential (masked in editor). "Users can configure
  global variables to apply automatically to specific fields by using the Apply To Fields
  menu. Once saved, these variables can be accessed in any text input field that displays
  the Globe icon." (configuration-global-variables)
- Prompt fields support {variable} curly-brace references; saved variables appear as input
  fields; values can come from global variables. (components-prompts)
- Workflow API v2 supports run-scoped "globals" injection (mode: sync) — relevant only if
  parent runs via HTTP API instead of MCP run_flow.
- CONFIG RISK for build phase: create_flow_from_spec "config:" lines set literal field
  values. The Gemini component's api_key is a Credential/SecretString field bound via the
  Globe icon (Apply To Fields). MCP configure_component sets literal param values — writing
  "GEMINI_API_KEY" as a string value there would be a LITERAL, not a global reference.
  Therefore: DO NOT set B.api_key in spec config or configure_component. Rely on the
  server-side "Apply To Fields" auto-binding of the existing GEMINI_API_KEY global
  (parent/user-side UI setting), or the credential's field-level default binding. This
  must be confirmed at build time on validation on register_discharge_summary (no scratch flow); export_flow redacts
  credential values so it is safe to inspect the bound field name afterwards.
- No tool exists to LIST or CREATE global variables over MCP — discovery confirms this is
